🤖 小机器人是怎么回答问题的？

greensam-cli 的心脏：ReAct 循环（对应源码 AgentLoop.java）· 2026-08-28

🎬 先记住一个名字：ReAct = 想一想 + 动动手

Reason（想一想）+ Act（动动手）。 小机器人回答你的问题，靠的不是一口气说完， 而是不停地「想一步 → 做一步 → 再想一步」，转圈圈，直到能回答你为止。

就像你找饼干：先想「饼干会在哪？」→ 看柜子（没有）→ 再想「那冰箱呢？」→ 看冰箱（找到啦！）→ 告诉妈妈「饼干在冰箱里」。 找一次不够就再找一次——这就是 ReAct。

这就是那个圈：想 → 做 → 想 → 做 → …… → 直接回答才下车

🎞️ 实战小剧场：「项目里有几个 Java 文件？」

第 1 轮转圈圈
🧒 你（写入本本）项目里有几个 Java 文件？
🧠 大脑（第 1 次想）我不知道文件数，但我可以用 glob 工具去数一数 → 请求调用工具！
🔧 工具箱执行，结果写入本本glob(pattern="**\/*.java") → 找到 34 个文件：AgentLoop.java, Repl.java, …
第 2 轮转圈圈
🧠 大脑（第 2 次想，这次本本里多了工具结果）哦！本本上写着 34 个，我可以直接回答了，不需要工具。
🤖 最终回答（写入本本 + 念给你听）项目里一共有 34 个 Java 文件。🏁

两次「想一想」，一次「动动手」——本本上每一步都留了痕，所以大脑永远不会失忆。

🛡️ 两条保命规则

🌀 最多转 20 圈

大脑可能犯傻：「用工具 A → 结果又让它用工具 A……」停不下来。 代码里 MAX_ITERATIONS = 20：转到 20 圈还不回答，就强行刹车并报错 （抛出 AgentLoopException），绝不转晕倒。

😭 工具失败了不哭，也不认输

工具报错时不会终止循环，而是把「错误: …」也当作工具结果写进小本本 （executeTools 里的 try/catch）。这样大脑下轮能看到失败原因，换个办法重试—— 就像你摔了一跤，爬起来换条路走。
